Nicrypt-Stego Delivery Sprints (Aligned to SPEC.md)¶

Sprint 0 - Project Setup (0.5-1 week) Goal - Confirm scope, success criteria, and delivery milestones.

Scope (SPEC.md references) - Section 3 (Objectives) - Section 4 (System Architecture)

Exit criteria - Agreed scope and versioned roadmap. - Repo scaffolding and CI baseline in place.

Sprint 1 - API and Facades (1-2 weeks) Goal - Deliver API surface and facades that match the spec, with stable inputs/outputs.

Scope (SPEC.md references) - Section 5.4 (High-Level API) - Section 6 (Data Flow Example) - Section 11 (Testing Strategy)

Deliverables - [x] REST API, SDK/CLI stubs, and request/response schemas. - [x] Auth and key management stubs for enterprise workflow. - [x] Model ops endpoints and status tracking. - [x] Logging, request IDs, and basic ops readiness.

Exit criteria - [x] OpenAPI spec and stubs are consistent and validated. - [x] End-to-end mock flow works (protect/verify with placeholders). - [x] Model ops endpoints working (pull/status). - [x] Request IDs emitted and visible in responses/logs.

Sprint 2 - Stego Engine MVP (2-3 weeks) Goal - Implement real token-level embedding/extraction with deterministic settings.

Scope (SPEC.md references) - Section 5.2 (Steganographic Embedder) - Section 5.3 (Steganographic Extractor) - Section 8.4 (Model Dependency)

Deliverables - [x] Embedding/extraction working with a small local model (e.g., gpt2). - [x] Deterministic model hash pinned to config. - [x] Redundancy (ECC-style) bit repetition with majority vote. - [x] Benchmarks and QA scripts for MVP and LLM backends.

Exit criteria - [x] Extracted ciphertext matches embedded ciphertext for test cases. - [x] Capacity benchmarks for 1-3 bits/token. - [x] LLM tiny model end-to-end flow validated. - [x] QA scripts documented and runnable.

Sprint 3 - Nicrypt Integration + Provenance Proof (1-2 weeks) Goal - Full protect/verify flow with encryption and decryption.

Scope (SPEC.md references) - Section 5.1 (Nicrypt Integration) - Section 6 (Data Flow Example)

Deliverables - [x] End-to-end pipeline: encrypt -> embed -> extract -> decrypt. - [x] Key management and environment variable handling.

Exit criteria - [x] Integration tests pass for protect/verify cycles. (Guarded by RUN_NICRYPT_TESTS=1) - [x] Documentation for key usage and configuration.

Sprint 4 - Robustness and Quality (2-3 weeks) Goal - Improve resilience and output quality.

Scope (SPEC.md references) - Section 7 (Capacity and Performance) - Section 8.2 (Robustness to Text Modification) - Section 12 (Limitations and Future Work)

Deliverables - [x] Add error-correcting codes (e.g., Reed-Solomon or BCH) beyond bit repetition. - [x] Robustness tests against perturbations (whitespace, punctuation, truncation, light shuffling). - [x] Fluency/perplexity evaluation and quality gates. - [x] Benchmarks extended with robustness metrics and ECC comparisons. - [x] Developer UX guardrails (capacity checks, dry_run/recommendations). - [x] Docs updates for robustness and ECC tradeoffs.

Exit criteria - [x] Demonstrated robustness on minor perturbations. - [x] Quality degradation <10% target where possible. Status notes - Robustness verified with tail_guard_tokens=24 and shuffle_window=2 (MVP). - Quality target met with expanded wordlist + template punctuation.

Sprint 5 - Packaging and Release (1-2 weeks) Goal - Ship a production-ready package and ops-ready service.

Scope (SPEC.md references) - Section 9 (Dependencies) - Section 10 (Installation & Setup) - Section 11 (Testing Strategy)

Deliverables - [x] Packaging polish (versioning, metadata, README validation). - [x] Deployment guides (local, server, enterprise). - [x] CI-ready test matrix and release checks. - [x] Benchmarks and example workflows finalized.

Exit criteria - [x] Release candidate build with docs and CI. - [x] Enterprise deployment checklist.

Sprint 6 - Gateway Integration (Exchange/Postfix) (1-2 weeks) Goal - Provide production-grade gateway integration guidance and automation hooks.

Scope (SPEC.md references) - Section 4 (System Architecture) - Section 10 (Installation & Setup) - Section 11 (Testing Strategy)

Deliverables - [x] Exchange integration recipe (Transport Rule / Agent flow). - [x] Postfix integration recipe (milter/header checks). - [x] Header verification endpoint usage (/v1/provenance/verify_headers). - [x] Gateway stamp example and SIEM/audit log guidance. - [x] Operator runbook for rollout and rollback.

Exit criteria - [x] End-to-end header verification documented for Exchange and Postfix. - [x] Operational steps validated with SMTP PoC.

Sprint 7 - Client UX (Gmail/Outlook) (1-2 weeks) Goal - Deliver user-facing verification badges and automation for mail clients.

Scope - Gmail extension (header-based badge). - Outlook add-in UX (concept + skeleton). - Automation for header verification.

Deliverables - [x] Gmail extension reads header-derived verification and shows badge. - [x] Outlook add-in scaffold with verification badge and status panel. - [x] Header verification automation hooks documented. - [x] Gmail extension supports attachment verification summary and partial badge state.

Exit criteria - [x] Gmail badge flow validated with header stamps. - [x] Outlook add-in scaffold reviewed (settings UI + attachment verify support). Status notes - Gmail extension now supports visible NS-SIGNATURE (compact token) and toggled verification panel. - Gateway relay + inbound stamping now validated end-to-end with Gmail attachment verification.

Sprint 8 - Production Readiness (2-3 weeks) Goal - Make the system deployable and operable in institutional environments with security, reliability, and observability standards.

Deliverables (prioritized) - [x] Key management + rotation policy (env/key vault integration, explicit rotation doc). - [x] Multi-tenant scoping (org_id, per-tenant keys, rate limits/quotas). - [x] Request auditing + retention (audit log schema, retention policy, export hooks). - [x] Reliability hardening (queueing/retries for SMTP/IMAP, backpressure limits). - [ ] Observability stack (structured logs + metrics + health endpoints in all daemons). - [ ] Deployment automation (Helm/Terraform or Docker compose for production).

Numbered Tasks (with Owners + Definition of Done) 1. Task: Key management + rotation integration. Owner: Backend/Platform. DoD: KMS/env adapter implemented, rotation steps documented, rotation test passes. 2. Task: Tenant isolation + quotas. Owner: Backend. DoD: org_id scoped storage + auth, rate limits enforced, multi-tenant tests added. 3. Task: Audit logging + retention. Owner: Backend/Security. DoD: append-only audit log schema, retention policy doc, export command added. 4. Task: SMTP/IMAP reliability hardening. Owner: Infra. DoD: queue + retry implemented, backpressure limits set, failure metrics emitted. 5. Task: Observability rollout. Owner: Infra. DoD: metrics endpoint + dashboards documented, structured logs include request_id everywhere. 6. Task: Deployment automation. Owner: DevOps. DoD: Helm/Terraform or prod Docker compose, verified deploy on Linux + Windows.

Exit criteria - [x] Tenant isolation and quota enforcement validated. - [x] Audit logs and rotation policies documented and tested. - [ ] Production deployment recipe verified on Linux + Windows. Status notes - Key management: keyring + file-based adapter (KEY_SOURCE/KEY_MATERIAL_PATH) with rotation test. - Tenant isolation: org-scoped key access, per-org policy overrides, endpoint limits by org, provenance store partitioning. - Audit logging: export/prune scripts support partitioned logs; tests added for retention/export. - Reliability: SMTP relay + inbound daemon + IMAP watcher now support queues, retries, and timeouts.

Sprint 9 - Technical Protection (1 week) Goal - Lock down SDK usage with enforceable technical controls (license, scopes, server-side protections).

Deliverables - [x] Technical protection checklist documented and linked to runtime controls. - [x] Vendor-signed license tokens (Ed25519 / JWKS) for offline SDK usage control. - [x] License verification endpoint (/v1/licenses/verify, no auth) + JWKS endpoint. - [x] License issuance and revocation endpoints (/v1/licenses/issue, /v1/licenses/revoke). - [x] Verifier enforcement toggle (LICENSE_REQUIRED=1) wired into verify endpoints. - [x] Licensed offline embed workflow documented: docs/LICENSED_OFFLINE_EMBED.md. - [ ] License enforcement at embed/sign boundary (deny embedding/signing without valid license where required). - [x] License token binding (enforce token org_id matches request org_id; enforce features gates per operation). - [x] Short TTL + renewal workflow (refresh endpoint + documented refresh path). - [x] Revocation distribution hardening (optional persistent store + caching strategy; avoid single-file bottlenecks). - [x] Audit trail for license lifecycle events (issue/refresh/revoke logged with org_id/lic_id/jti/exp/features).

Exit criteria - [x] Checklist reviewed and referenced in ops docs. - [x] Embed/sign endpoints demonstrably blocked without a valid license when enforcement is enabled. - [x] License-bound features enforced in at least one production-relevant flow (offline embed + signature issuance).

Sprint 10 - Certificate Provenance (Institutions) (1-2 weeks) Goal - Issue and verify tamper‑evident electronic certificates (PDFs) for institutional use.

Deliverables - [x] Certificate issuance script (embed provenance in PDF/DOCX metadata). - [x] Certificate verification API + CLI helper (file upload -> status + metadata). - [ ] Gateway attachment provenance integration for certificate flows. - [ ] Issuer + recipient documentation.

Exit criteria - [ ] End-to-end demo (issue -> send -> verify in mail + file). (Email delivery flow pending) Notes - Full plan: docs/CERTIFICATE_PROVENANCE_SPRINT.md

Production Workflow: Email Provenance¶

Overview Production deployments should avoid relying on email body steganography in consumer clients. Use SMTP header injection for outbound mail and header verification on inbound mail.

Certificate provenance For institutional certificates (PDFs), see docs/CERTIFICATE_PROVENANCE_SPRINT.md.

Email vs Certificate Provenance (Quick Comparison) See docs/EMAIL_VS_CERTIFICATE_COMPARISON.md.

Outbound (Signing) 1. Email is created in the organization’s mail system. 2. SMTP relay injects provenance headers: - X-Provenance-Ciphertext - X-Provenance-Model - X-Provenance-BPT - X-Provenance-Timestamp - X-Provenance-KeyId 3. Email is delivered without modifying the visible body.

Inbound (Verification) 1. Mail gateway or client reads provenance headers. 2. Verify via /v1/provenance/verify_headers. 3. UI displays Verified/Unverified badge.

Gateway Stamp (PoC) Use poc/gateway_stamp.py to turn inbound headers into verification headers:

python poc/gateway_stamp.py /path/to/message.eml

Example output headers:

X-Provenance-Verified: true
X-Provenance-Reason: ok
X-Provenance-Model-Hash: mhash_...
X-Provenance-Timestamp: 2026-02-15T...

Policy Enforcement Use apps/api/server/config/policy.yaml to enforce which sender domains must include provenance.

Example

required_sender_domains:
  - veriforensic.com
allow_missing_provenance: false

PoC Tools - poc/smtp_sender.py for direct SMTP sending with headers. - poc/smtp_relay.py as a lightweight header‑injecting relay. - poc/verify_headers.py for verifying .eml files.

Operational Checklist - Rotate keys and keep key ids in headers. - Lock model hashes for stable verification. - Enable audit logging for header verification.

Daemon Config - poc/daemon_config.env for inbound verifier settings. - poc/nicrypt-*.service legacy templates (deprecated; do not copy as-is). - scripts/systemd_render.py renders correct systemd unit files for the current repo root.

Install systemd service (example)

make install-services ENABLE_IMAP=1
make enable-services ENABLE_IMAP=1
make start-services ENABLE_IMAP=1
make status-services ENABLE_IMAP=1

Outbound relay systemd (example)

make install-services ENABLE_IMAP=0
make enable-services ENABLE_IMAP=0
make start-services ENABLE_IMAP=0
make status-services ENABLE_IMAP=0

systemd override example

sudo systemctl edit nicrypt-inbound.service

Then add:

[Service]
Environment="STAMP_BODY=1"
Environment="INBOUND_SMTP_PORT=587"

Outbound override example

sudo systemctl edit nicrypt-outbound.service

Then add:

[Service]
Environment="SMTP_PORT=587"

IMAP override example

sudo systemctl edit nicrypt-imap.service

Then add:

[Service]
Environment="IMAP_HOST=mail.privateemail.com"
Environment="IMAP_USE_KEYWORDS=1"

IMAP Watcher Report Run with --report to print per-cycle totals:

python poc/imap_watcher.py --report

IMAP Watcher Health Default health endpoint on 127.0.0.1:8100 (configurable via IMAP_HEALTH_PORT).

IMAP Watcher Options - --all to process all messages (not just UNSEEN) - --label-only to avoid moving messages - --audit-log /path/file.jsonl to append JSONL audit records

launchd log override (macOS) Edit the plist to change log paths:

~/Library/LaunchAgents/com.nicrypt.imap.plist

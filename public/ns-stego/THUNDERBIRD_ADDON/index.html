Thunderbird Add-on (Verifier)¶

Purpose Verify provenance headers in Thunderbird using the Nicrypt-Stego API.

What it verifies - Message provenance via X-Provenance-* headers. - Attachment provenance via X-Provenance-Attachment. - A single badge verdict via POST /v1/provenance/verdict (recommended).

Prerequisites - API running at http://127.0.0.1:8125/v1 - A valid JWT token (see docs/quickstart.md) - A message that passed through the gateway relay/inbound flow

Install (temporary add-on) 1) Open Thunderbird. 2) Tools -> Add-ons and Themes -> gear icon -> Debug Add-ons. 3) Load Temporary Add-on and select: poc/thunderbird-addon/manifest.json

Install (packaged) 1) Build the add-on: make package-addons 2) Install the generated XPI: dist/addons/thunderbird-addon.xpi

Configure settings 1) Click the add-on toolbar button or open Add-ons and choose Options. 2) Set: - API Base: http://127.0.0.1:8125/v1 - API Token: your JWT 3) Click Save Settings.

Verify a message - Select a message, then: - Click the toolbar button and press "Verify Selected", or - Right-click a message -> Verify provenance, or - Use shortcut: Ctrl+Shift+V

Stego (invisible text) test 1) Generate and send a stego email:

python scripts/send_stego_email.py \
  --token $TOKEN \
  --secret "alice@example.com|2026-02-17|Stego QA" \
  --cover "a short compliance memo about retention policies" \
  --from "sender@example.com" \
  --to "your-thunderbird-inbox@example.com"

2) Open the email in Thunderbird and run "Verify Selected".

Plain email + provenance headers (gateway relay) Use this when you want a normal human message and header-only provenance:

python scripts/send_plain_gateway_email.py \
  --token $TOKEN \
  --secret "alerts@yourbank.com|2026-02-17|Bank Notice" \
  --from "alerts@yourbank.com" \
  --to "your-thunderbird-inbox@example.com" \
  --subject "Account notice" \
  --body "Hello, this is your bank. Please review the update."

Expected results - Verified: shows sender/provenance string, model hash, timestamp, policy. - Partial: message verified but some attachments fail. - Unverified: missing headers or policy failure.

Gateway flow required (recommended) Messages must pass through the gateway to include the provenance headers.

One-command gateway bootstrap:

make bootstrap-gateway ENABLE_IMAP=0

Provenance secret Set PROVENANCE_SECRET to control what appears as "Sender" in verification results. Example:

PROVENANCE_SECRET="sender@example.com|2026-02-17|Email QA"

Notes - Thunderbird can read full headers; no Gmail-style body stamping is required. - If you see "Policy: missing_provenance", the message did not pass through the gateway.

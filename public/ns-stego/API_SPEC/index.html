Nicrypt-Stego API Spec (v1)¶

Decision: REST + JSON Rationale: easiest enterprise integration, works with standard gateways, audit tooling, and log pipelines. gRPC can be added later as a parallel interface.

Base URL - /v1

Auth - Bearer tokens (JWT or opaque) via Authorization header. - Optional mTLS for internal deployments. - All write operations require scope-based authorization. - Multi-tenant support via org_id in JWT (or X-Org-Id header). - Rate limits and quotas are enforced per org.

Content Types - Request: application/json - Response: application/json

Common Fields - model_name: string - bits_per_token: integer (1-4, default 2) - max_new_tokens: integer (default 200) - model_hash: string (server-computed, stable hash of model + tokenizer + config + sampling params) - request_id: string (server-generated UUID) - org_id: string (derived from JWT or X-Org-Id header)

Endpoints

1) Create key profile POST /v1/keys Request { "name": "legal-team-2026", "rotation_policy": "annual", "metadata": { "owner": "legal", "purpose": "authorship-provenance" } } Response { "key_id": "key_9f4d2", "name": "legal-team-2026", "rotation_policy": "annual", "created_at": "2026-02-13T10:30:00Z" }

2) List key profiles GET /v1/keys Response { "keys": [ { "key_id": "key_9f4d2", "name": "legal-team-2026", "rotation_policy": "annual", "created_at": "2026-02-13T10:30:00Z" } ] }

Note: Keys are scoped to org_id. Requests from one org cannot list or rotate keys from another org.

3) Rotate key POST /v1/keys/{key_id}/rotate Response { "key_id": "key_9f4d2", "rotated_at": "2026-02-13T10:40:00Z", "status": "rotated" }

4) Embed provenance (encrypt + embed) POST /v1/provenance/embed Request { "secret": "Alice Johnson, 2026-02-12, CC-BY-NC", "cover_prompt": "a short compliance memo about data retention", "model_name": "meta-llama/Llama-3-8B", "bits_per_token": 2, "max_new_tokens": 220, "key_id": "key_9f4d2" } Response { "request_id": "req_1b2c3", "stego_text": "...", "model_hash": "mhash_7e83...", "payload_bytes": 92, "tokens_used": 214 }

5) Embed ciphertext (embed only) POST /v1/provenance/embed_cipher Request { "ciphertext": "gAAAAABl...", "cover_prompt": "a short compliance memo about data retention", "model_name": "meta-llama/Llama-3-8B", "bits_per_token": 2, "max_new_tokens": 220 } Response { "request_id": "req_1b2c3", "stego_text": "...", "model_hash": "mhash_7e83...", "payload_bytes": 132, "tokens_used": 214 }

6) Extract ciphertext POST /v1/provenance/extract Request { "stego_text": "...", "model_name": "meta-llama/Llama-3-8B", "bits_per_token": 2 } Response { "request_id": "req_4d5e6", "ciphertext": "gAAAAABl...", "model_hash": "mhash_7e83...", "confidence": 0.93 }

7) Verify (extract + decrypt) POST /v1/provenance/verify Request { "stego_text": "...", "model_name": "meta-llama/Llama-3-8B", "bits_per_token": 2, "key_id": "key_9f4d2" } Response { "request_id": "req_4d5e6", "secret": "Alice Johnson, 2026-02-12, CC-BY-NC", "verified": true, "model_hash": "mhash_7e83...", "metadata": { "detected": true, "tampered": false } }

8) List models GET /v1/models Response { "models": [ { "model_name": "meta-llama/Llama-3-8B", "model_hash": "mhash_7e83...", "context_length": 8192, "notes": "Production baseline" } ] }

Note: Model pull/status tracking is scoped per org.

9) Pull model POST /v1/models/pull Request { "model_name": "meta-llama/Llama-3-8B" } Response { "status": "queued", "model_name": "meta-llama/Llama-3-8B" }

Note: Model pull status is stored per org_id.

10) Health GET /v1/health Response { "status": "ok", "uptime_s": 104233 }

11) Metrics GET /v1/metrics Response { "format": "prometheus" } Note: Metrics requires auth and is scoped by org_id for rate limiting.

Error Model All errors return: { "request_id": "req_...", "error": { "code": "MODEL_NOT_FOUND", "message": "Model not available on server", "details": { "model_name": "meta-llama/Llama-3-8B" } } }

Error Codes - INVALID_REQUEST - AUTH_REQUIRED - AUTH_FORBIDDEN - KEY_NOT_FOUND - KEY_ROTATION_FAILED - MODEL_NOT_FOUND - MODEL_MISMATCH - INVALID_BITS_PER_TOKEN - PAYLOAD_TOO_LARGE - EXTRACTION_FAILED - DECRYPTION_FAILED - RATE_LIMITED - INTERNAL_ERROR

Security Constraints - Scope-based access control (example scopes: provenance:embed, provenance:verify, keys:manage, models:read, models:pull). - All provenance write operations logged with request_id, key_id, model_hash, and payload_bytes. - Optional tamper-evidence: append audit hash to server logs (hash chain per day). - mTLS optional for internal deployments. - Encrypt key material at rest using KMS or HSM.

Notes - Deterministic settings required for extraction. The server pins model_name, tokenizer version, and sampling parameters into model_hash. - If model_hash mismatch is detected, extraction returns MODEL_MISMATCH unless override is allowed.

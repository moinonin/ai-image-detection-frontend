Document Workflow (Readable by Default)¶

Goal - Keep documents (research papers, reports, legal docs) fully readable. - Attach provenance without changing visible content.

Recommended Approach 1) Extract text from the document. 2) Create a provenance ciphertext from the secret. 3) Store the ciphertext in metadata (not in the visible body).

Why this works - The original document remains unchanged and readable. - Metadata travels with the file in most enterprise workflows. - Verification can happen at gateways or client tools without altering content.

PDF (recommended) - Store metadata in XMP or custom PDF metadata fields. - Use keys like: - X-Provenance-Ciphertext - X-Provenance-Model - X-Provenance-Bpt - X-Provenance-Timestamp

DOCX (recommended) - Use custom document properties: - X-Provenance-Ciphertext - X-Provenance-Model - X-Provenance-Bpt - X-Provenance-Timestamp

Verification flow 1) Extract metadata. 2) Call /v1/provenance/verify_headers with those fields mapped into headers. 3) If verified, display a badge or audit stamp.

Notes - Some platforms strip metadata. For those, use gateway stamping or archive systems. - For high-risk flows, keep a secondary copy of the ciphertext in a secure audit log.

Certificate issuance For institution-issued certificates and reprints, see docs/CERTIFICATE_PROVENANCE_SPRINT.md.

Upload Gateway (Provenance Proxy)¶

Goal - Sit between uploaders and existing document portals. - Embed provenance automatically while keeping documents readable. - Forward the same files to the institution’s existing storage/archive.

High-Level Flow 1) User uploads to gateway. 2) Gateway extracts text and encrypts provenance. 3) Gateway writes metadata into file (PDF/DOCX). 4) Gateway forwards file to the upstream portal (S3/SharePoint/ResearchGate/etc). 5) Gateway logs the audit record and returns receipt to user.

Why this works - No change to archive/back-end systems. - Minimal workflow change for users. - Provenance embedded before storage, preserved at rest.

Core Components - Upload API (multipart form): /v1/gateway/upload - Metadata embedder (PDF/DOCX) - Upstream connector (S3, SharePoint, ResearchGate, custom API) - Audit log + receipt ID - Optional verification endpoint for downstream checks

Gateway API (proposed) POST /v1/gateway/upload Headers - Authorization: Bearer Response headers (gateway) - X-Provenance-Ciphertext - X-Provenance-Model - X-Provenance-BPT - X-Provenance-Timestamp - X-Provenance-Attachment (per file) Body (multipart/form-data) - file: binary - secret: string - metadata_mode: "pdf" | "docx" | "auto" - upstream_target: "s3" | "sharepoint" | "custom" - upstream_url: string (optional for custom)

Example (local embed + forward)

curl -sS -X POST http://127.0.0.1:8125/v1/gateway/upload \
  -H "Authorization: Bearer $TOKEN" \
  -F "file=@paper.pdf" \
  -F "secret=alice@example.com|2026-02-15|Paper" \
  -F "author=Alice Johnson" \
  -F "title=Provenance Research" \
  -F "subject=Data Provenance" \
  -F "keywords=provenance,compliance,ai" \
  -F "metadata_mode=auto" \
  -F "upstream_url=https://your-portal.example.com/upload"

Presigned S3 upload

curl -sS -X POST http://127.0.0.1:8125/v1/gateway/upload \
  -H "Authorization: Bearer $TOKEN" \
  -F "file=@paper.pdf" \
  -F "secret=alice@example.com|2026-02-15|Paper" \
  -F "upstream_s3_bucket=my-bucket" \
  -F "upstream_s3_key=archive/paper.pdf" \
  -F "upstream_s3_presign=true"

SharePoint connector (PUT)

curl -sS -X POST http://127.0.0.1:8125/v1/gateway/upload \
  -H "Authorization: Bearer $TOKEN" \
  -F "file=@paper.pdf" \
  -F "secret=alice@example.com|2026-02-15|Paper" \
  -F "upstream_sharepoint_url=https://tenant.sharepoint.com/sites/site/_api/web/GetFolderByServerRelativeUrl('Shared%20Documents')/Files/add(url='paper.pdf',overwrite=true)" \
  -F "upstream_sharepoint_token=$SP_TOKEN"

Extract metadata (verify later)

curl -sS -X POST http://127.0.0.1:8125/v1/gateway/metadata \
  -H "Authorization: Bearer $TOKEN" \
  -F "file=@paper.pdf" \
  -F "provenance_only=true" \
  -F 'expected_keys_json=["X-Provenance-Ciphertext","X-Provenance-Model","X-Provenance-Bpt","X-Provenance-Timestamp"]'

Verify metadata (badge result)

curl -sS -X POST http://127.0.0.1:8125/v1/gateway/verify \
  -H "Authorization: Bearer $TOKEN" \
  -F "file=@paper.pdf"

Batch upload

curl -sS -X POST http://127.0.0.1:8125/v1/gateway/upload_batch \
  -H "Authorization: Bearer $TOKEN" \
  -F "files=@paper.pdf" \
  -F "manifest_json=$(cat manifest.json)" \
  -F "strict_filename=false"

Manifest example (supports local_path)

{
  "items": [
    {
      "filename": "paper.pdf",
      "local_path": "paper.pdf",
      "secret": "alice@example.com|2026-02-15|Paper",
      "metadata_mode": "auto"
    }
  ]
}

Response { "request_id": "req_abc123", "status": "forwarded", "ciphertext": "gAAAAAB...", "model_hash": "mhash_123456", "receipt_id": "rcpt_7890", "upstream_ref": "portal-asset-id" }

Metadata embedding rules - PDF: XMP or custom metadata keys - X-Provenance-Ciphertext - X-Provenance-Model - X-Provenance-Bpt - X-Provenance-Timestamp - DOCX: custom document properties with same keys

Upstream forwarding modes 1) Direct API proxy (HTTP/S3/SharePoint) 2) File drop (shared folder) 3) Email relay (for journals / repositories)

Security & Compliance - Tenant-scoped keys and quotas. - Full audit log (append-only). - Optional request signing for upstream portals.

Rollout Plan 1) Pilot on one repository (e.g., departmental archive). 2) Enable audit log + verification tooling. 3) Expand to multi-tenant orgs and portals.

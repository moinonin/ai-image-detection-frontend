Quickstart¶

This is the daily workflow cheat-sheet for running and verifying Nicrypt-Stego.

0) Start the API¶

. .venv/bin/activate
PYTHONPATH=apps/api JWT_SECRET=dev-secret uvicorn server.app:app --reload --port 8125

1) Create a full-scope JWT (dev)¶

export TOKEN="$(JWT_SECRET=dev-secret python scripts/gen_token.py)"

1b) Issue a vendor license token (Sprint 9)¶

If LICENSE_REQUIRED_FOR_EMBED=1 or LICENSE_REQUIRED_FOR_SIGNATURE=1 is enabled on the API, you must supply a license_token when issuing certificates or signature tokens.

Issue a license (requires a JWT with licenses:issue):

curl -sS -X POST http://127.0.0.1:8125/v1/licenses/issue \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "org_id":"public",
    "lic_id":"lic_demo",
    "ttl_seconds":3600,
    "features":{
      "offline_embed":true,
      "signature_issue":true
    }
  }'

Then export the returned value as LICENSE_TOKEN for later calls:

export LICENSE_TOKEN="v1.<vendor_payload>.<vendor_sig>"

2) Embed provenance (text)¶

curl -sS -X POST http://127.0.0.1:8125/v1/provenance/embed \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "secret":"you@example.com|2026-02-15|Email QA",
    "cover_prompt":"a short compliance memo",
    "backend":"mvp",
    "bits_per_token":3,
    "max_new_tokens":700,
    "auto_expand":true,
    "auto_expand_margin":50
  }'

2b) Standalone SDK smoke test (no API)¶

If you see ValueError: Payload too large for max_new_tokens, estimate capacity first and set max_new_tokens = needed + margin.

. .venv/bin/activate
python - <<'PY'
from nicrypt_stego.provenance import estimate_capacity, protect, verify

secret = "alice@example.com|2026-02-15|SDK smoke"
topic = "Subject: Test\n\nHello team,\nThis is a cover memo.\n"

cfg = dict(
    backend="mvp",
    model_name="sshleifer/tiny-gpt2",
    bits_per_token=3,  # must match on verify()
    redundancy=1,
    ecc_mode="repetition",
    ecc_symbols=16,
)

needed = estimate_capacity(secret, **cfg)
max_new_tokens = needed + 50

stego = protect(secret=secret, topic=topic, max_new_tokens=max_new_tokens, **cfg)
out = verify(stego_text=stego, topic=topic, max_new_tokens=max_new_tokens, **cfg)

print("verified:", out == secret)
print("extracted:", out)
PY

3) Verify (ciphertext-only, recommended)¶

curl -sS -X POST http://127.0.0.1:8125/v1/provenance/verify \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "ciphertext":"gAAAAAB...",
    "model_name":"sshleifer/tiny-gpt2",
    "bits_per_token":4
  }'

4) File embed¶

curl -sS -X POST http://127.0.0.1:8125/v1/provenance/embed_file \
  -H "Authorization: Bearer $TOKEN" \
  -F "file=@/path/doc.pdf" \
  -F "cover_prompt=Policy update memo." \
  -F "backend=mvp" \
  -F "bits_per_token=3" \
  -F "max_new_tokens=700" \
  -F "auto_expand=true" \
  -F "auto_expand_margin=50"

5) Verify email headers (recommended production)¶

curl -sS -X POST http://127.0.0.1:8125/v1/provenance/verify_headers \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "headers": {
      "From": "Acme Bank <alerts@yourbank.com>",
      "X-Provenance-Ciphertext": "gAAAAAB...",
      "X-Provenance-Model": "sshleifer/tiny-gpt2",
      "X-Provenance-Bpt": "4",
      "X-Provenance-Timestamp": "2026-02-15T12:00:00Z"
    }
  }'

5b) Verify a Raw Email (.eml) (preprocess + verify)¶

Instead of manually sifting through huge header blocks, upload the entire RFC822 message:

python scripts/verify_email.py /path/to/message.eml --api-base http://127.0.0.1:8125/v1 --api-token "$TOKEN" --print-extracted

5c) Compute a Single Badge Verdict (recommended for plugins/gateways)¶

Use this when you want a single verified/unverified/partial status without hand-parsing:

python scripts/verify_email.py /path/to/message.eml --api-base http://127.0.0.1:8125/v1 --api-token "$TOKEN" --verdict

6) Outbound SMTP PoC (adds headers automatically)¶

python poc/smtp_sender.py \
  --subject "Provenance QA" \
  --body "This is a QA email with provenance headers." \
  --secret "qa@veriforensic.com|2026-02-15|Email QA"

7) Gateway relay + inbound stamping (recommended)¶

One-command bootstrap (relay + inbound, IMAP disabled by default).

Recommended setup (so you don’t need a huge env list every time): - Put your API JWT in /tmp/api_token.jwt (or set API_TOKEN / API_TOKEN_PATH). - Put your license JWT in /tmp/provenance_license.jwt (or set PROVENANCE_LICENSE_TOKEN_PATH). - Put SMTP creds in .env (INBOUND_SMTP_HOST, INBOUND_SMTP_USER, INBOUND_SMTP_PASS). (.env.example is treated as defaults only.)

make bootstrap-gateway ENABLE_IMAP=0

Restart later (no giant env list)

make restart-services ENABLE_IMAP=0

Ports: - Outbound relay listens on 2525 (signs + adds attachment header) - Inbound daemon listens on 2527 (stamps HTML for Gmail)

Gateway flow (relay + inbound):

Sender -> [smtp_relay.py:2525] -> [smtp_inbound_daemon.py:2527] -> SMTP Provider -> Gmail
                       (adds X-Provenance-Attachment)       (stamps data-provenance-attachments)

Minimal marker policy (recommended) - In Gmail, the verifier primarily uses NS-SIG-LINK / ns_sig=... (a deterministic body marker) because webmail UIs can’t reliably expose raw headers to extensions. - Some SMTP providers rewrite <a href="..."> links for click-tracking; the gateway also carries ns_sig=... in HTML attributes so the Gmail extension can still extract it. - The inbound gateway shows a minimal visible badge like 🔒 ns-stego verified and embeds the machine markers in a hidden HTML block.

Quick check:

make post-check-services ENABLE_IMAP=0

Gateway status (pretty view):

make gateway-status

Example output:

8) Gmail Extension PoC (attachments)¶

  • Works only if hidden markers are present (inbound daemon with STAMP_BODY=1).
  • Uses ciphertext markers, not headers (Gmail doesn’t expose headers to extensions).
  • Shows verified badge near sender and attachment verification summary.

Send an attachment test through the relay:

python scripts/send_signed_attachment.py --mail-to you@example.com --attach /tmp/binance_stamped.pdf

Deterministic QA (skip waiting on email delivery):

# Write tokens to files once per shell/session (avoids quoting issues).
echo "$TOKEN" > /tmp/api_token.jwt
echo "$LICENSE_TOKEN" > /tmp/license_token.jwt

python scripts/send_signed_attachment.py \
  --mail-to you@example.com \
  --attach /tmp/binance_stamped.pdf \
  --qa-id "$(date +%Y%m%d-%H%M%S)" \
  --save-eml /tmp/nicrypt-last.eml \
  --api-token "$(cat /tmp/api_token.jwt)" \
  --license-token-path /tmp/license_token.jwt

python scripts/verify_email.py /tmp/nicrypt-last.eml \
  --api-base http://127.0.0.1:8125/v1 \
  --api-token "$(cat /tmp/api_token.jwt)" \
  --verdict

Notes: - Don’t use command substitution (e.g. $(...)) inside .env files. Export tokens in your shell instead. - --license-token-path expects a filesystem path (e.g. /tmp/license_token.jwt). - Do not pass the file contents to --license-token-path (use --license-token for that).

9b) Issue + Verify a Certificate (Sprint 10)¶

Stamp a PDF/DOCX by embedding X-Provenance-* into file metadata (PDF info dict / DOCX custom properties).

Note: if the API is running with LICENSE_REQUIRED_FOR_EMBED=1, pass --license-token "$LICENSE_TOKEN".

python scripts/issue_certificate.py \
  --api-base http://127.0.0.1:8125/v1 \
  --api-token "$TOKEN" \
  --in docs/CoverLetterBinance.pdf \
  --out /tmp/binance_stamped.pdf \
  --issuer-id "uni:example" \
  --cert-id "cert:123" \
  --recipient-id "person:alice" \
  --secret "person:alice" \
  --license-token "$LICENSE_TOKEN"

Verify the stamped file:

python scripts/verify_certificate.py \
  --api-base http://127.0.0.1:8125/v1 \
  --api-token "$TOKEN" \
  --in /tmp/binance_stamped.pdf

10) Model status (per org)¶

make model-status ORG_ID=org_a

11) Batch embed (files)¶

Create a manifest.json:

{
  "items": [
    {
      "filename": "paper.pdf",
      "local_path": "paper.pdf",
      "secret": "alice@example.com|2026-02-15|Research Paper",
      "cover_prompt": "research paper on cryptographic provenance",
      "model_name": "sshleifer/tiny-gpt2",
      "bits_per_token": 3,
      "max_new_tokens": 700
    }
  ]
}

Run:

curl -sS -X POST http://127.0.0.1:8125/v1/provenance/embed_file_batch \
  -H "Authorization: Bearer $TOKEN" \
  -F "files=@paper.pdf" \
  -F "manifest_json=$(cat manifest.json)" \
  -F "strict_filename=false"

14) Gateway metadata extract¶

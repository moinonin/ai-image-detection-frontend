Technical Protection Checklist (SDK)¶

Scope This checklist focuses on technical enforcement and operational controls that protect SDK use and prevent unauthorized embedding or signing.

Identity and Licensing - [x] License validation enforced at API boundary (via LICENSE_REQUIRED=1). - [x] License expiry/renewal path implemented (/v1/licenses/issue with exp) and tested. - [x] Capability tokens (time-boxed) issued per org + scope (license token includes org_id + features + exp). - [x] Token revocation path implemented and tested (/v1/licenses/revoke by jti). - [x] Public key distribution implemented (JWKS: /v1/.well-known/jwks.json). - [x] Offline embed pattern documented (see docs/LICENSED_OFFLINE_EMBED.md). - [x] Optional embed/sign boundary enforcement (LICENSE_REQUIRED_FOR_EMBED=1, LICENSE_REQUIRED_FOR_SIGNATURE=1). - [x] License token binding enforced (token org_id must match request org_id; features gates per operation). - [x] License renewal path implemented (/v1/licenses/refresh) and tested. - [x] Revocation storage hardened (JSON or SQLite backend + small TTL cache). - [x] License lifecycle events audited (issue/refresh/revoke recorded in provenance store when enabled). - [x] Swagger/OpenAPI examples include org_id/lic_id/ttl_seconds for license issuance and include license_token on embed/sign examples for easy manual testing.

Auth and Scope Enforcement - [ ] All embed/sign endpoints require scopes (provenance:embed, signature:issue). - [ ] Verify endpoints remain accessible with least-privilege scopes. - [ ] Per-org policy enforcement (sender domains, required provenance). - [ ] API rejects missing/invalid org_id in multi-tenant mode.

Server-Side IP Protection - [ ] Core embedding/quality logic stays server-side (thin clients). - [ ] Model hash and capacity checks enforced server-side. - [ ] Request/response schemas do not leak secrets or key material.

Key Management - [ ] Key source selectable (env, file, KMS). - [ ] Rotation procedure documented and automated. - [ ] Key usage is logged (audit trail). - [ ] Decryption fails cleanly on key mismatch.

Telemetry and Auditing - [ ] Structured logs include org_id + request_id + endpoint. - [ ] Audit log records embed/sign/verify actions. - [ ] Retention + export policies documented.

Rate Limits and Abuse Controls - [ ] Per-org throughput limits (embed/verify/sign). - [ ] Burst control and backpressure configured. - [ ] Invalid token attempts rate-limited.

Client UX Protections - [ ] Verified badge shown only on server-verified status. - [ ] “Partial” status when attachments fail verification. - [ ] No local-only verification claims.

Gateway Protections - [ ] Relay→inbound chain enforced (stamp body for Gmail). - [ ] Attachment header stamping enabled for outbound. - [ ] SMTP STARTTLS behavior correct for local hop.

Deployment Hardening - [ ] Service env vars sourced securely (not hardcoded). - [ ] Health endpoints available for monitoring. - [ ] CI verifies enforcement paths (license + scopes).

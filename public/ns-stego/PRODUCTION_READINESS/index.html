Production Readiness Checklist¶

Technical protection - See docs/TECHNICAL_PROTECTION_CHECKLIST.md for license enforcement, scope gating, and abuse controls.

Priority 1 (Security + Trust) - Key management + rotation (KMS/HSM optional). - Per-tenant key isolation (org_id scoping). - Policy enforcement in API + gateway flows. - Auditable provenance logs (append-only, signed, exportable).

Priority 2 (Reliability + Scale) - Queue + retry for SMTP/IMAP flows. - Rate limits and backpressure. - Dead-letter queue for failures. - Idempotency for embed/verify jobs. - Per-endpoint quotas per org (embed/verify).

Endpoint Limits (config) Example (per-org limits by endpoint):

export ENDPOINT_LIMITS_JSON='{
  "org_a": {
    "/v1/provenance/embed": {"per_min": 10, "per_day": 1000},
    "/v1/provenance/verify": {"per_min": 20}
  },
  "default": {
    "/v1/provenance/embed": {"per_min": 5}
  }
}'

Priority 3 (Observability + Ops) - Metrics (latency, success rate, capacity failures). - Health endpoints in all daemons. - Log correlation via request_id everywhere. - Alerting thresholds for failures.

Priority 4 (Client UX) - Header-based badges (Gmail/Outlook). - Admin dashboard (verification stats, failure drilldowns). - End-user explainers for verified/unverified.

Priority 5 (Compliance + Legal) - Retention policies and deletion windows. - PII handling and redaction. - DPIA template for institutions. - Per-org provenance storage separation (when enabling persistence).

Estimates (high level) - P1: 1.5-2.0 weeks - P2: 1.0-1.5 weeks - P3: 0.5-1.0 weeks - P4: 1.0-1.5 weeks - P5: 0.5-1.0 weeks
